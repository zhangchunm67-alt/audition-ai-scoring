## S2：选择 A，先确认字段，不降低门槛

只填 fixed_script 不够。s2_material() 要求：fixed_script.text 非空、fixed_script.version 非空；s2_calibration.version 非空；s2_calibration.fixed_script_version 与 fixed_script.version 完全一致。

产品资料中发布参考脚本，版本 script-2026-11；实际完成产品 S2 校准后录入其真实版本和对应话术版本。校准记录通常还含 status、train_samples、holdout_samples、holdout_agreement、anchors 和 note。当前就绪函数只检查前述字段及版本匹配，不代表样本量或准确率达标；未验证校准仍须标为非正式。不可编造校准版本、样本或一致率来通过门槛。本交付未改业务库、未将材料自动发布为正式脚本。

机器直接生效时验收 score 非空及 status=scored；suggested_score 是供人工确认的机器建议分，直接生效场景可以为空，不应以它作为失败条件。

## P3：验证前不开发 provider

缺少这次 1 分钟朗读音频、20 句人工标签、部署机 Omni 的实际结果，尚不能计算准确率或决定投入。P3 保持原人工路径，不接零样本机器评分。

验证需记录每句音频起止、参考原句、人工声母/韵母/声调标签、Omni 对应判定、逐句一致性；保留请求模型版本和原始输出，不将 ASR 输出当人工真值。20 句至少 16 句达到预先约定的一致判据才进入下一阶段；80% 只是开发推进门槛，不是上线校准结论。录播无参考稿的评测须另标“无参考清晰度/声调评估”，不能冒充带参考朗读的对错判断，也不能直接更改 P3 原评分协议。

## 部署与验收

部署前保留当前热补丁副本和数据备份。解压源码不能替代重建镜像；勿直接 compose up 回退到旧镜像。网络恢复后按清单重建镜像，再启动容器。

运行 python -m app.cli init-config 导入 v4（仅新增，重复执行跳过），已有 v3 不改写。导入前后检查检测版本选择：若有已发布旧配置，runner 会优先选 published，不能仅凭导入成功认定切到 v4；部署机当前全为 draft 时会选最新新增 v4。最终以新报告 trace.detector_config_version 和 model_manifest 为准。

检查容器 7 个 running、migrate 退出码 0、API 200；新传无异议片段，确认 P5/P6/P7/O4 scored 且 score 有值、有 O4 证据；S1/S2/L1 仍需人工确认，P3 仍人工。S2 有合格材料才产机器建议分；没有材料时转人工符合预期。本机 Mock 测试仅证明程序链路，不代表部署机真实模型验收。

回滚使用上一提交重建镜像。新报告的 detectors-v4 / prompts-v6 与旧报告版本清单分开追溯。
