# PRD · 主播试镜 AI 评分 v1

Nov 1, 2026 · @Eric

v1 做一套结构化试镜工具：候选人按固定流程录 17 分钟试镜，AI 按《主播评分标准 · 机器可执行版 v0.1》自动出分、出证据、出报告，全程无人工复核。评分结果作为录用、转正、绩效的参考，不单独作为决定依据；直播评分是 v2。

## 0. 关键规则速览

v1 评分全自动，以下五条规则决定系统怎么处理特殊情况，细节以评分标准文档为准。

| 规则 | 是什么 | 系统怎么处理 |
| --- | --- | --- |
| 红线 | 违反保险营销合规的说法，如“稳赚不赔”“什么都能报”“不买孩子出事你后悔一辈子”“最后 10 单”“加我微信单独聊”（共 8 类 R1–R8） | 模型置信度达到阈值即判定命中，结论直接为“不达标”，分数照常出；报告附原句、时间点和正确说法 |
| 临界 | 总档位离达标线 2 档以内，小误差就可能翻转结论（新主播试播要求 < 15，即 13–16） | 自动重跑 3 次取多数结论，报告标“临界”，提醒 HR 谨慎使用 |
| 低置信 | 模型对某条的判断把握不足（如转写不清） | 照常出分，报告标出，计入准确度统计 |
| 音色删除 | 音色无法可靠自动评判，已从标准中移除 | 人设塑造满分 95，按实得分 ÷ 95 × 100 折算后查档位；共 23 条 |
| 校准 | 判断 AI 准不准的唯一依据 | 上线前 2–3 位同事手工打 20–30 条作金标准；上线后每月抽 10–20 条核对 |

## 1. 背景与目标

v1 要把试镜打分从“有人从头看视频、手填 4 张表”改成 AI 全自动评分：日常不占用人力，每个候选人用同一把尺子，每一分都留证据。

现在的问题有三个：候选人录的内容不统一，分数不可比；每条视频都要人从头看；扣分没有证据，候选人拿不到具体反馈。

| 目标 | 指标 | v1 目标值 |
| --- | --- | --- |
| 省人力 | 每条试镜的人工时间 | 0（只有上线前校准和每月抽样核对） |
| 准确 | AI 与金标准的维度档位相差 ≤ 1 档的比例 | ≥ 85% |
| 准确 | 达标 / 不达标结论与金标准一致的比例 | ≥ 95% |
| 合规 | 红线召回率 / 误报率（金标准集） | ≥ 95% / ≤ 5% |
| 体验 | 提交到出报告 | ≤ 30 分钟 |

以上目标值先按此执行，校准完成后按实测调整。因为没有人工兜底，准确度没达标不上线。

## 2. 范围

v1 只做试镜场景，覆盖从配置、录制、AI 自动评分到报告的完整闭环；直播评分留给 v2。

| v1 做 | v1 不做 |
| --- | --- |
| 结构化试镜录制（手机 H5 / 电脑浏览器） | 直播实时提醒、逐轮打分、场后复盘（v2） |
| AI 全自动评分：23 条条目 + 红线检测 + 临界样本自动重跑 | 日常人工复核 |
| 试镜报告：内部版 + 候选人反馈版 | 与 HR / 招聘系统打通（先用 Excel 导出） |
| 配置后台：评分标准、卖点卡、异议库、题库、朗读稿、红线词表 | 按数据自动调整评分权重 |
| 校准工具：金标准打分、每月抽样核对、准确度看板 | 多子公司 / 多租户权限 |

## 3. 角色与核心流程

日常流程里只有三个人工动作：管理员建批次、候选人录制、HR 看报告；中间的评分全部由系统完成。

| 角色 | 是谁 | 在 v1 里做什么 |
| --- | --- | --- |
| 候选人 | 应聘主播、待试播的新主播 | 打开邀请链接，授权、录制、提交 |
| 管理员 | 负责主播招聘或培养的同事 | 维护评分标准、卖点卡、题库，创建试镜批次，看准确度看板 |
| 合规 | 合规部门 | 维护红线词表和正确说法 |
| 校准员 | 2–3 位熟悉评分表的同事 | 上线前给金标准集打分；每月抽 10–20 条核对 |
| HR | 招聘、主播管理 | 看报告、导出结果、做录用和转正决定 |

1. **建批次**：管理员选产品卖点卡、异议库、题库，生成邀请链接发给候选人。
2. **录制**：候选人授权 → 设备检测 → 准备 15 分钟 → 录主体段 10 分钟、知识题 6 道、朗读 1 分钟 → 提交。可以在家用手机录，也可以来公司直播间录；在家录不考道具使用。
3. **自动评分**：系统转写、找证据、算分、查红线；临界样本自动重跑 3 次取多数。
4. **出报告**：30 分钟内生成内部报告；HR 查看或导出；候选人不收到任何分数，反馈版只发给已录用的新主播，用于试播前辅导。

## 4. 功能需求

v1 分六个模块，P0 是上线必须有的，P1 可以在试用期补上。评分规则一律以《主播评分标准 · 机器可执行版》为准，本文不重复。

### M1 配置后台

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M1-1 | 评分标准版本管理：导入计分配置，条目参数可改，每份报告记录所用版本 | P0 |
| M1-2 | 产品卖点卡：必讲要点（分值、是否合规必讲）、针对性卖点、场景、术语白话对照、关键数字、禁用说法 | P0 |
| M1-3 | 异议库、知识题库、朗读稿的增删改；按产品配置抽题规则（异议 4 条、知识题 6 道） | P0 |
| M1-4 | 试镜批次：选产品和材料，生成邀请链接，设有效期和可录制次数 | P0 |
| M1-5 | 红线词表与正确说法，仅合规角色可编辑 | P0 |
| M1-6 | 按条目设置低置信阈值和红线判定阈值 | P1 |

### M2 候选人录制端

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M2-1 | 授权页：说明采集视频、人脸、声音的用途和保存期限，单独勾选同意并留存记录；不同意则无法继续 | P0 |
| M2-2 | 设备检测：摄像头、麦克风音量、底噪、光线、网速，不合格给出改进提示 | P0 |
| M2-3 | 准备页：展示卖点卡，15 分钟倒计时，可提前开始 | P0 |
| M2-4 | 主体段录制：10 分钟计时，在 04:00、05:30、07:00、08:00 弹出异议弹幕，一镜到底不可暂停 | P0 |
| M2-5 | 知识问答：逐题显示，每题 60 秒，可提前进入下一题；朗读段显示文稿 | P0 |
| M2-6 | 上传：分片上传、断点续传、进度显示；录制中断允许重录 1 次 | P0 |
| M2-7 | 录制期间切屏、切后台记录，写入报告供 HR 参考 | P1 |

### M3 AI 处理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M3-1 | 逐字转写：关闭顺滑，保留语气词，字级时间戳，分段（主体段 / 每道题 / 朗读） | P0 |
| M3-2 | 声学特征：静音、语速、音高、音量、笑声；朗读段普通话评测 | P0 |
| M3-3 | 各条目检测器按评分标准输出证据（标准第 9 节的证据结构） | P0 |
| M3-4 | 红线检测：词表召回 + 大模型判断，命中全部标为待确认 | P0 |
| M3-5 | 计分引擎：按配置算条目分、维度分、档位、总档位、结论；证据变更后即时重算 | P0 |
| M3-6 | 抽帧与画面分析，给 AI 辅助条目标候选片段（形象、小动作、道具、笑场） | P1 |
| M3-7 | 稳定性检查：同一录像跑两次，条目分相差超过满分 10% 标为不稳定 | P1 |

### M4 自动判定规则

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M4-1 | 红线：模型置信度达到阈值即判定命中，结论为“不达标”；阈值可配置 | P0 |
| M4-2 | 临界样本：总档位离达标线 2 档以内，自动重跑 3 次取多数结论，报告标“临界” | P0 |
| M4-3 | 低置信条目：照常出分，报告中标出并计入准确度统计 | P0 |
| M4-4 | 处理失败：自动重试 2 次，仍失败则通知候选人重录并告警 | P0 |

### M5 报告

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M5-1 | 内部报告：结论、总档位、四个维度分和档位、每条得分与证据、红线、临界和低置信标记、标准版本、模型版本 | P0 |
| M5-2 | 批次导出 Excel，单份报告导出 PDF | P0 |
| M5-3 | 候选人反馈版：每个维度扣分最多的 2–3 处，附原句、时间点和改法，不含内部结论 | P1 |
| M5-4 | 结论标签：报告顶部显示“推荐 / 待定 / 不推荐”。推荐 = 达标且非临界、无红线；待定 = 临界样本；不推荐 = 不达标或命中红线。标签下方一句话说明原因 | P0 |
| M5-5 | 批次排名：同一批次候选人按分数排序（先按结论标签，再按总档位从低到高，同档按四个维度分之和从高到低）；可按标签、维度筛选，可切换按单个维度排序；支持导出 | P0 |
| M5-6 | 逐句评分与改进建议：逐字稿按句展示，每句标出命中的条目、加扣分和原因，有问题的句子附示范说法；点句子跳到视频对应时间。仅公司员工账号可见，不对试镜候选人开放；已录用的新主播入职后可看自己的记录 | P0 |

### M6 校准与看板

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M6-1 | 金标准集：同一录像分给 2–3 位校准员背对背打分，系统算人和人的一致率 | P0 |
| M6-2 | 一致率看板：按条目、批次看 AI 与金标准 / 月度抽样的一致比例，低于目标时告警 | P1 |
| M6-3 | 效率看板：处理时长、失败率、各条目低置信比例 | P1 |

## 5. 非功能需求

重点是个人信息保护和可追溯：候选人还不是员工，视频里有人脸和声音，每个分数都要能说清楚来源。

| 类别 | 要求 |
| --- | --- |
| 时效 | 提交后 30 分钟内出报告；报告页 3 秒内打开，证据可点开听原声 |
| 容量 | 每月约 100 条试镜，峰值 5 条同时录制或处理，按此部署，处理队列可横向扩容 |
| 稳定 | 上传断点续传；AI 处理失败自动重试 2 次，仍失败则通知候选人重录并告警 |
| 一致 | 大模型固定版本、温度 0；换模型或改提示词前，先在金标准集上跑回归，一致率不下降才发布 |
| 授权 | 视频、人脸、声音采集前单独同意，记录同意时间和文本版本；候选人可申请删除 |
| 权限 | 校准员只看抽中的样本；逐句评分和改进建议只对公司员工账号开放，候选人端不显示任何分数；HR 看报告不看原始视频（可申请）；所有查看和导出留日志 |
| 存储 | 传输和存储加密；数据和模型调用都在境内；未录用候选人的视频到期自动删除（具体天数由法务 / HR 定，系统按配置执行） |
| 追溯 | 每份报告记录评分标准版本、模型版本、各条目的证据和置信度 |
| 兼容 | 录制端支持 iOS / Android 主流浏览器和微信内置浏览器、桌面 Chrome / Edge；管理后台和报告只支持桌面 |

## 6. 验收标准与上线计划

分四步上线；因为没有人工兜底，准确度在金标准集和试用批次上都达标才正式上线。

| 阶段 | 做什么 | 出口标准 |
| --- | --- | --- |
| 0 校准准备 | 收集 20–30 条历史试镜或内部主播录制；2–3 位校准员背对背打分 | 金标准集定稿；评分标准待确认项已拍板 |
| 1 内测 | 全部 P0 功能；AI 在金标准集上跑分 | 达到第 1 节的准确和合规指标 |
| 2 影子试用 | 1–2 个真实招聘批次，AI 出分但结果不作为参考，校准员全量核对 | 结论一致 ≥ 95%，红线无漏判、无大量误报 |
| 3 正式上线 | AI 结果作为录用参考；每月抽 10–20 条核对 | 月度准确度不低于目标，否则回到阶段 1 |

内测的 P0 验收用例：

- [ ] 不同意授权时无法进入录制
- [ ] 4 条异议弹幕按配置的时间点弹出，证据时间戳与视频对得上
- [ ] 口头禅在转写中保留，未被顺滑删掉
- [ ] 人设塑造按 95 分满分正确折算
- [ ] 红线命中时结论为“不达标”，报告附原句
- [ ] 临界样本自动重跑 3 次，报告标“临界”
- [ ] 报告里的标准版本、模型版本完整
- [ ] 到期视频自动删除，报告保留

## 7. 风险与依赖

最大的风险是没有人工兜底：AI 判错会直接进入录用参考，所以上线前必须过影子试用，上线后每月抽样核对。

| 风险 | 应对 |
| --- | --- |
| 红线误报，候选人被错判“不达标” | 判定阈值先调保守；报告附原句，HR 可以自己听；不设申诉，结论只作参考，由 HR 结合原句自行判断 |
| 临界样本结论不稳 | 自动重跑取多数；报告标“临界”提醒 HR 谨慎使用 |
| 转写质量差（方言、噪音、手机收音） | 录制前设备检测；低置信标记 |
| 大模型判断漂移 | 固定版本；变更前跑金标准回归；月度抽样 |
| 候选人对 AI 评分有意见 | 授权页说明评分方式；不对相貌评分；结果只作参考 |
| 合规口径变化 | 红线词表由合规在后台维护，不依赖发版 |

**依赖**

- 评分标准 21 项待确认拍板（培训、合规、产品）
- 第一款产品的卖点卡、异议库（≥ 20 条）、题库（≥ 30 题）、朗读稿（培训）
- 红线词表和正确说法（合规）
- 语音识别、语音评测、大模型、存储的供应商选型，须境内、支持逐字转写（研发）
- 20–30 条校准录像和 2–3 位校准员的打分时间
