# 决定与待确认记录

本文件记录：两份需求文档之间的冲突、已拍板的业务规则、按已确认规则推导出的实现口径、尚未拍板的问题，以及纯技术决定。
**2026-11-06 起，计分规则以 `docs/source/主播评分表-20261105.xls` 为唯一来源（第 7 节）**；`docs/rubric.md` 及第 1–4 节中由它推出、与新表冲突的口径（C1、C2 的满分、C7、C25、Q9、Q12、Q14、Q18、P-B3、P-P3-ACCENT、P-P5 等）已作废，保留原文供追溯。**待确认的规则不得静默进入正式配置**：配置里对应节点带 `pending` 或 `calibration_required` 标记，`scoring.publish_blockers()` 会全部列出，清零前不能发布（`status: published` 的配置在加载时也会被拒绝）。

编号约定：X = 文档冲突，C = 已确认，I = 实现口径（请复核），P/Q = 待确认（Q 为 rubric 第 12 节原编号），T = 技术决定，A = 后续验收补充。

### 4.5 上线门槛与校准统计（已按推荐确认为 C34、C35；以下是原建议方案，保留备查）

仍待定：样本量。Q20 要求“每批 ≥ 30 条、连续 2 批”，PRD 是金标准 20–30 条、影子试用 1–2 批、月度 10–20 条。系统不强制样本量，看板显示定稿样本数，由管理员按定下的标准判断。另外 PRD“换模型或改提示词前先在金标准集上跑回归”目前要手动做（重新处理金标准样本后看一致率），没有一键回归。
（P-Q20、P-GOLD）

**P-Q20 建议方案（待确认）**：
1. 系统上线门槛以 PRD 第 1、6 节为准：维度档位相差 ≤1 档的比例 ≥85%，结论一致 ≥95%，红线召回 ≥95%、误报 ≤5%，影子试用结论一致 ≥95%。
2. Q20 的数值原本用于“逐条放开出分方式”（人工 → AI 辅助 → AI 初评 → AI 出分）。v1 全部条目已由 AI 出分，不再逐条放开，建议改为**条目级监控线**：某条目与金标准的一致率低于 85% 时告警，先改该条的规则或提示词，不单独阻止上线。
3. 样本量冲突：Q20 要求“每批 ≥30 条、连续 2 批”，PRD 金标准集为 20–30 条、影子试用 1–2 批、月度抽检 10–20 条，需要确定以哪个为准。

**P-GOLD 需要确定的统计口径（建议，待确认）**：
1. **金标准如何形成**：2–3 位校准员背对背打到证据级。建议把每位校准员的证据送进同一个计分引擎得出各自的分数；条目分取中位数（2 人时取平均），差异超过条目满分 20% 的条目开会裁决；结论由裁决后的证据经引擎计算得出。
2. **人与人一致率（M6-1）**：按“样本 × 维度”统计档位相差 ≤1 的比例，并单列结论一致率。
3. **分母**：
   - 维度档位一致率 = 样本数 × 4；
   - 结论一致率 = 金标准集样本数。AI 结果不完整（缺必需证据）的样本计为不一致，不从分母剔除；
   - 临界样本用 3 轮后的最终结论参与统计；
   - 红线召回 = AI 命中的金标准红线句数 ÷ 金标准红线句数，时间差在 ±3 秒内算同一句；
   - 红线误报率 = 金标准无红线、AI 却判了红线的样本数 ÷ 金标准无红线的样本数；
   - 低置信条目照常计入（PRD M4-3）。

## 5. 技术决定

| 编号 | 决定 |
|---|---|
| T1 | 代码在 `zhangchunm67-alt/audition-ai-scoring`，分支 `claude/blissful-mendel-204ozp`，基于 main 的初始提交 |
| T2 | 计分全程使用 `fractions.Fraction`，只在维度分取整时用 half-up；不用 Python 内置 `round`（银行家舍入，`round(90.5) == 90`） |
| T3 | 计分配置（分值、档位、阈值，改了只需重算）与检测配置（词表、抽帧率、提示词，改了需重跑模型）分开版本管理；报告同时记录两者以及模型清单 |
| T4 | 证据结构在 rubric 第 9 节基础上加 3 个可选字段：`ref`（要点、题目或异议 id、子项名）、`value`（指标数值）、`segment`（main / question / reading）；`judgment` 可以是数字（等级分）。检测器尽量输出比当前规则多的证据（如沉没成本促成句、L1 的钩子是否合规），这样待确认项拍板后多数只需改配置 |
| T5 | 缺失证据：检测器未成功完成，或该类型必需的证据不存在（如 T4 没有等级、T5 没有指标、S2 有要点未核对、T6 有题没有判定），条目状态为 `missing_evidence`、不出分，维度和本轮不出结论。检测器已完成且没有扣分事件（T1、T2 的空证据）才是真正的零次 |
| T6 | 证据与配置不符（未知条目、证据类型不对、等级不在锚定表内、重复证据）直接报错，不静默忽略 |
| T7 | 逐句贡献：T1 按时间顺序，前 N 处免扣，之后逐处扣分；T2 按时间顺序加到封顶为止。只影响逐句展示，不影响分数 |
| T8 | 数据库用 PostgreSQL，主键 UUID，配置快照、证据判定、计分结果用 JSONB；迁移用 Alembic，降级时同时清理枚举类型 |
| T9 | `transcripts` 表加约束 `NOT disfluency_removal`：写入时必须关闭顺滑 |
